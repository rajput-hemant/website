# Edition redundancy audit

Snapshot: source tree on `fm/portfolio-edition-refactor` after F1-F6, route loaders, command-menu hook, Radix declaration removal, and Timetable ask OG alignment. Visual and e2e gates are still open; this audit describes code structure, not pixel parity. `E` means all six editions: `minimal`, `drawing-set`, `surface`, `survey`, `timetable`, `press`. Paths beginning `flavors/E/` or `app/f/E/` expand to every existing path in that set. [The full file inventory](redundancy-inventory.tsv) names every file under `flavors/`, `app/f/`, `components/semantic/`, and `lib/`, its behavior family, same-relative-path peers, same-name candidates, and exact-byte peers. Same-name and byte matches were triage only; the verdicts below use the actual imports and behavior.

Regenerate the inventory with `bun scripts/redundancy-inventory.ts` (1,051 rows at `4cc0ce3`).

The prior [two-edition review](shared-code-review.md) has largely been implemented: shared ask client, pending store, owner provider, composer, moderation, command matching/controller, preference store factory, lab shader/scene, resume loader, visit counter, and link-preview state already exist. The current problem is concentrated in route wrappers, edition-specific adapters that still perform behavior, and cross-layer imports. Exact bytes alone do not justify moving a styled component.

A shared file may contain data loading, state, events, pure transformation, a headless hook, or an unstyled/render-prop primitive. It may not import `flavors/*`, switch on an edition, select an edition's labels or tokens, or render edition styling. `components/semantic` is for headless React; `lib` is for non-React or server logic. Editions retain markup, copy, CSS, motion choreography, and preference schema.

## Dead code, dependencies and structural checks

- Static source-literal scan found no source references to `styled-components`, `tw-animate-css`, or `web-vitals`. Detailed evidence and verdicts are recorded below under Dependencies.
- The exact-copy groups contain redundant `index.ts` re-export files and tests, but they are not presumed dead: imports must be traced before deletion. No other export is marked safe to delete from this static pass. A tool such as Knip can propose more candidates, but a Next convention export, dynamic import or Sanity schema can look unused in a naive scan.
- One import cycle was detected: `flavors/drawing-set/components/site/scene-slot.tsx` -> `scene-posters.tsx` -> `scene-slot.tsx`. The reverse edge is type-only; move `SceneRoute`'s type import in `scene-posters.tsx` to `flavors/drawing-set/lib/scene/poses.ts` to make ownership clear.
- Metadata and JSON-LD mostly use `lib/metadata.ts` and `lib/ask/pages/metadata.ts`. The route files still duplicate `generateMetadata` wrappers. Keep each route file required by Next; consolidate only the lookup and metadata calculation.
- The shared-data layer already uses one Sanity accessor set. No edition-owned Sanity query or API client was found. Shared `lib/command` no longer imports `flavors/registry`; edition-specific href mapping stays in local command dialogs.

### Detailed evidence

#### 1. `@radix-ui/react-dialog`

- **Baseline declaration**: `"@radix-ui/react-dialog": "^1.1.23"`
- **Knip output**: `Unused dependencies (2): @radix-ui/react-dialog package.json:58:6`
- **Depcheck output**: Flagged in `dependencies` array as unused.
- **Source verification (`git grep`)**: Zero imports across all application source files. Minimal's command dialog (`flavors/minimal/components/command/command-dialog.tsx`) was refactored to `@base-ui/react` Dialog.
- **Transitive graph**: `cmdk@1.1.1` specifies `@radix-ui/react-dialog: "^1.1.6"` as an internal dependency. The project policy permits `cmdk` and its transitive Radix dependencies while eliminating direct Radix declarations.
- **Action**: Direct declaration dropped from `package.json` and `bun.lock` in commit `2dda667`.

#### 2. `web-vitals`

- **Declaration**: `"web-vitals": "^6.2.2"`
- **Knip output**: `Unused dependencies (1): web-vitals package.json:84:6`
- **Depcheck output**: Flagged in `dependencies` array as unused.
- **Source verification (`git grep`)**:
  - `git grep -E 'from ["'\'']web-vitals|require\(["'\'']web-vitals'` returns 0 matches in application source code.
  - The only literal occurrence in codebase files is `eslint.config.mjs` importing `eslint-config-next/core-web-vitals` (which is part of the ESLint config package, not `web-vitals`).
  - Historical reference: `docs/plan.md` mentions `web-vitals` was planned for an LCP/INP/CLS attribution debug overlay (`?debug`) that was not implemented.
- **Transitive graph**: `sanity@6.16.0` lists `web-vitals: "^6.2.2"` in its own dependencies.
- **Action**: Confirmed candidate for removal from direct dependencies.

#### 3. `styled-components`

- **Declaration**: `"styled-components": "^6.5.3"`
- **Knip output**: Not flagged as unused due to Knip's Sanity plugin recognizing peer dependency requirements.
- **Depcheck output**: Listed as used across Sanity structure, schemas, and studio files due to depcheck's built-in Sanity detector.
- **Source verification (`git grep`)**:
  - Zero imports (`import ... from "styled-components"`) in application or flavor source files.
- **Transitive / Peer dependency graph**:
  - `@sanity/ui@4.2.4`: `peerDependencies: { "styled-components": "^6.1" }`
  - `sanity@6.16.0`: `peerDependencies: { "styled-components": "^6.1.15" }`
  - `next-sanity@13.3.4`: `peerDependencies: { "styled-components": "^6.1" }`
  - `@sanity/visual-editing@6.1.2`: `peerDependencies: { "styled-components": "^6.1" }`
- **Action**: Retained. The embedded Sanity Studio (`app/studio/[[...tool]]/page.tsx`) renders `@sanity/ui` components at runtime, which require `styled-components` in the resolution tree.

#### 4. `tw-animate-css`

- **Declaration**: `"tw-animate-css": "^1.4.0"`
- **Knip output**: Not flagged.
- **Depcheck output**: Flagged as unused because `depcheck` analyzes JS/TS import ASTs and ignores CSS stylesheets.
- **Source verification (`git grep`)**:
  - Confirmed active import in `flavors/minimal/styles.css`:
    ```css
    @import "tw-animate-css";
    ```
- **Action**: **Do not remove.** Actively required by Minimal edition styles.

#### 5. Tooling and devDependencies verification

- `bunx knip --dependencies` reported `@axe-core/playwright` as an unused devDependency due to TypeScript alias resolution inside `playwright.config.ts`; confirmed actively imported and executed in `e2e/a11y.spec.ts`.
- `bunx depcheck` reported build, formatting, and linting tools (`@commitlint/cli`, `@commitlint/config-conventional`, `@ianvs/prettier-plugin-sort-imports`, `@tailwindcss/postcss`, `lint-staged`, `prettier-plugin-tailwindcss`, `tailwindcss`) as unused because they are CLI commands or configuration plugins rather than module imports. ## Verification baseline for execution

## Migration discoveries

- `cmdk` brings Radix packages transitively. The owner permits these transitive packages and wants `cmdk` retained. Direct `@radix-ui/react-dialog` use and declaration are removed; Minimal's dialog uses Base UI.
- Survey's relief-backed neighbor order returns `SurveyNeighbour[]`, not `Project[]`. Its project route uses shared static params and metadata; body and navigation loading stay local to preserve refs and order.
