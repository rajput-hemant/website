# Shared code review: Minimal and Drawing Set

This is an implementation plan, not a source change. Paths are relative to the repository root. `M` below means `flavors/minimal`; `D` means `flavors/drawing-set`. A path such as `M/components/ask/api.ts` expands to `flavors/minimal/components/ask/api.ts`.

## Boundary and evidence

Both live editions have 19 route files. The flavor trees have 199 Minimal files and 182 Drawing Set files; 93 files have the same relative path. Direct text diff found exact copies in ask API, pending messages, owner provider, command highlight and recents, most lab shader files, link-preview loading and targeting, visitor-count hook, media-query hook, and continuity lanes. Example pairwise text ratios: ask API 1.00, pending messages 1.00, command menu 0.99 with different dynamic imports, preference store 1.00, link-preview layer 0.95, resume renderers 0.83-0.97, route ask page 0.58 and route resume page 0.77. These ratios are triage data, not a sharing rule. The verdict below follows behavior and imports. `lib/data`, `lib/ask`, `lib/command`, `lib/link-previews`, `lib/visits`, `lib/format`, `lib/metadata`, `lib/markdown`, `lib/resume`, and `lib/public-pathname` already hold shared contracts. Reuse them.

Rule: a shared file may contain data loading, state, events, pure transformation, a headless hook, or an unstyled/render-prop primitive. It may not import `flavors/*`, contain a flavor switch, choose an edition's labels or tokens, or render edition styling. Each edition owns its markup, copy, CSS, motion choreography and preference schema. `components/semantic` in `docs/flavors.md` is the place for the allowed headless React units; `lib/*` holds non-React or server logic. The planned `SplitHeading`/`Reveal` extraction is limited to a token-free motion driver. Current visual wrappers remain per edition.

## Target folders

```text
app/
  f/<edition>/                 # Route shells, metadata exports, redirects and edition composition; no copied data algorithm.
  api/, md/, ask/, studio/     # Existing shared endpoints and studio; never import an edition UI.
components/
  semantic/                   # Headless client hooks/context only; no classes, tokens, edition imports or styled JSX.
    ask/                      # Owner session, pending echo and composer/moderation state.
    command/                  # Command data/controller and keyboard behavior; accepts edition action inputs.
    link-preview/             # Hover/focus controller; caller supplies root and enabled state.
    visitor-count/            # Visit-count hook and data state.
    copy-email/               # Clipboard state and fallback hook.
lib/
  ask/                        # Existing server rules plus new client API and shared page loaders.
    pages/                    # Ask list/slug pagination, static params and metadata with no JSX.
  command/                    # Search types/index plus pure matching, history, shortcuts and fetch.
  data/                       # Existing Sanity accessors and shared continuity computation.
  link-previews/client/       # Client fetch cache and DOM target selection; existing server rules stay in parent.
  prefs/                      # Generic typed storage store factory only; never an edition schema.
  resume/                     # Existing URL helper plus server resume data loader.
  lab/                        # Shared experiment math, shaders, types and WebGL detection only.
flavors/<edition>/
  components/                 # All styled components and edition motion/scene presentations.
  lib/                        # Edition-specific prefs schema, bound prefs store, hash grammar, dates and cn tokens.
  content.ts, styles.css      # Edition navigation/copy and scoped design tokens; no backend copy.
```

Shared versus local decision: if changing a behavior should affect every edition and the code can express that without knowing an edition, put it under `lib` or `components/semantic`. If a value is a design choice, label, storage schema, route availability, scene content, CSS class or visual transition, leave it under `flavors/<edition>`. A small duplicated JSX wrapper is cheaper and safer than a prop-heavy shared component. Keep shared client imports out of server-only data modules and keep heavy lab/scene code behind its existing deferred boundary.

## Migration sequence

The batches are dependency ordered. Parallel lanes within each batch use disjoint files; explicit serial edges below override the batch grouping. Run one integration check after each batch. Do not parallelize two steps that edit the same file, or apply a later batch before its shared API exists. `bun run test -- <file>` denotes a focused Vitest run, not the full suite. The final gate lists the full commands for the implementer. Read the installed Next guide in `node_modules/next/dist/docs/` before writing route or client/server code; this review checkout did not contain `node_modules`.

## Risks and acceptance checks

- **Hydration and rewrite:** Client route logic must use `usePublicPathname()` from `lib/public-pathname.ts`, never direct `usePathname()`. Link preview destination checks should use `publicPath(window.location.pathname)` too. Check direct clean URLs and `/f/minimal/*` / `/f/drawing-set/*` rewrites against hydration and current-link behavior.
- **Client/server boundary:** `lib/ask/pages/*` and `lib/resume/load.ts` are server-side data only. Client hooks have `"use client"` and never import Sanity/server helpers. Do not pull 3D, GSAP, R3F, WebGL shaders or the command dialog into eager shared barrels. Keep dynamic imports and measure each route with `bun run budget`.
- **Preference isolation:** `hr.prefs` and `hr.ds.prefs` are separate JSON schemas and migrations. The factory must maintain separate snapshots and listeners, respect server defaults during hydration, and preserve cross-tab storage events. Minimal's pre-paint/client-root sync and Drawing Set's `data-scene` must stay intact.
- **Styling isolation:** Both `styles.css` files use `@import "tailwindcss" source(none)` and only `@source` their own flavor and route folders. Shared semantic code must carry no Tailwind classes. `.prettierrc` selects the correct stylesheet for each flavor; do not move styled JSX outside those overrides. Keep each `cn()` extension's text sizes, since one shared merge config can silently discard classes.
- **Behavioral contracts:** Preserve ask `hr.ask.pending`, command `hr.command.recent`, visit session/local keys, moderation errors, focus restoration, clipboard fallback, full-page edition switching, static-param growth and edition-specific scene events. Verify the shared hooks with focused tests before removing either copy.
